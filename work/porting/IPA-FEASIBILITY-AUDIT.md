## 二、D2R 是怎么解决这一步的

`docs/NO_XCODE.zh-CN.md` 给出的路线（**这条路本身是有效的**）：

```
① 出「壳」：一个不含任何游戏内容的 ipa（约 4 MB，只有宿主程序 + 图标 + 两张表）
       ← 需要 macOS + Xcode，用 dm/ios/tools/shell_build.sh
② 做包：d2rm_pack.py <壳.ipa> <游戏文件目录> <输出.ipa>
       ← 任意系统都能跑（Windows 实测整条走通，约 7 分钟；输出约 130 MB）
③ 装机：用自签工具（Sideloadly / AltStore / 爱思助手）签名安装
       ← 免费 Apple ID 即可；7 天过期、最多 3 台设备、每台 3 个 App
```

D2R 文档自己标了每一项的验证状态：

| 这一步 | D2R 的现状 |
|---|---|
| 壳 + 工具做出可玩的安装包 | ✅ 已在 Mac 与真机各走通一局 |
| 不用苹果的着色器编译器（Windows 做的包） | ✅ 真机验过进局 |
| 在 Windows 上跑这个工具 | ✅ **整条走通**（Windows 11、Python 3.12） |
| **用自签工具签名装机** | ⚠️ **「还没验过，欢迎开 Issue 告诉我们结果」** |

## 三、为什么「壳」这一步我绕不过去

### 3.1 壳必须用 Xcode 出

`dm/ios/tools/shell_build.sh` 是 **bash 脚本**，内部调 `xcodebuild`，且仓库里有
`dm/ios/project.yml`（XcodeGen 的项目定义）与 `DmIOS.xcodeproj` 的生成逻辑。
`docs/NO_XCODE.zh-CN.md:100` 明说：

> 「出壳的机器要有游戏文件**和全套构建环境**（和平常出包一样）」

### 3.2 壳是**游戏专属**的，不能用 D2R 的壳

这是关键 —— 即使我能下载到 D2R 的 `D2RMobile-shell.ipa`，**对本游戏也没用**，因为：

| 壳里有什么 | 为什么是 D2R 专属 |
|---|---|
| 宿主程序 | 已编译的 D2R 宿主（含它的 `hle_*.c`、`dm_*.c`、`nvn_mtl.m`） |
| 界面素材与数据表 | 从 D2R 的游戏文件生成的 |
| 「壳里缺什么」的清单 | 按 D2R 的内容核对表定的 |
| 着色器摘要 | 用于核对翻译结果与壳是否匹配 |

**本游戏的宿主是我在 `work/host/` 下从头写的**（`hle.c` / `loader.c` / `hle_nn*.c` /
`hle_nvn*.c`），与 D2R 的宿主是不同的程序。所以**必须为它出一个自己的壳**，
而出壳需要 Mac。

### 3.3 Windows 上能做的部分，我确实都做了

`d2rm_pack.py` 在 Windows 上能跑，是因为它只做「生成内容 + 塞进壳」，
**壳本身是输入参数**。我这边没有任何等价物可以替代那个输入。

## 四、三条现实路径（供用户选）

### 路径 A：借一台 Mac（一次性出壳，之后全靠 Windows）⭐ 推荐

**只需要用一次 Mac**：

```
在 Mac 上：装 Xcode → 跑 shell_build.sh → 得到 shell.ipa（约 4 MB）
之后全在 Windows：写本游戏的壳构建脚本 → 用我已有的 5 模块产物 + 116 个着色器出包
```

- 成本：借一台 Mac / 云 Mac 一小时
- 之后：**完全不需要 Mac**（做包、改代码、重出包都在 Windows）

**这条路与本项目已有的成果完全兼容** —— 我写的宿主、装载器、改写器、着色器链都直接可用。

### 路径 B：继续把 Windows 侧做到极致，暂不出包

把「不需要 Mac 的部分」全部做完并验证：

- ✅ 已完成：改写器、装载器、宿主 HLE（238/238）、NVN 接口/对象/录音/着色器桥/翻译层
- ⬜ 可继续：命令回放器、iOS 外壳的**源码**（`main.m` + 触摸 + 生命周期，
      写好但只能在 Mac 上编译）、打包脚本（把 5 模块产物组织成 ipa 内容）

**好处**：等有 Mac 时，剩下的只是「编译 + 出壳 + 塞内容」，一两天就能出包。
**风险**：iOS 外壳代码无法在 Windows 上编译验证，可能有编译错误要等 Mac 上才能修。

### 路径 C：换目标 —— 模拟器/串流（D2R 文档里也提到）

`FEASIBILITY.zh-CN.md` 里记着：**AltStore PAL 的 JIT 让 iPhone/iPad 可以全速跑
Switch 模拟器**。如果用户的目标只是「在 iPad 上玩到这个游戏」，那么：

- 用现成的 Switch 模拟器（Eden / Ryujinx 的 iOS 版）
- 用户已经有 Eden 且**已在这个游戏上运行成功**（第 1 轮确认过）

**这条路的成本是「几小时」，而自研移植是「人年」。**
D2R 作者自己的文档也把这条路列为对照方案。

## 五、我的建议（诚实版）

| 如果用户想要… | 建议 |
|---|---|
| **尽快在 iPad 上玩到这个游戏** | **路径 C** —— 用 Eden 的 iOS 版 + 用户的游戏文件。用户已经在 Eden 上跑通过，这条路的确定性最高 |
| **要一个不依赖模拟器的原生移植** | **路径 A** —— 借一次 Mac 出壳，之后全在 Windows。这需要一次性的 Mac 访问 |
| **暂时没有 Mac，也不想用模拟器** | **路径 B** —— 我继续把 Windows 侧做完，把出包需要的一切准备到「一键」的程度 |

**我不应该假装路径 A 或 B 能凭 Windows 单独走完最后一步。**
D2R 的文档在这一步上也是把「壳」定义为**预先构建好的输入**，而不是 Windows 能产出的东西。
