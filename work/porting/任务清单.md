### 已经解决的关键坎（都是「只有真机才暴露」的）

1. **iOS 不允许执行运行时写进内存的代码**（匿名页 mprotect 成可执行 → 一执行进程就被内核干掉）。
   → 改成 D2R 的做法：模块影像装进一个**会被代码签名**的 `Guest.framework/Guest`
   （`work/tools/guest_dylib.py` 生成），运行时只 `vm_remap` 已签名页。
2. **`dlopen` 的返回值不是 `mach_header`**（曾导致点开就闪退）。
   → 照 D2R：`_dyld_get_image_name/_dyld_get_image_header` 按映像名找。
3. **`_init`（DT_INIT）调 `nn::ro::ProtectRelro` 用 rtld 才填的字段** → 段错误。
   → `nn::ro*` 符号改走宿主 HLE；启动序列照 D2R 的脚本重排 8 步。
4. **主线程没向 SDK 登记**（SDK 从 `tpidrro_el0 + 0x1F8` 取当前线程，再读 `+0x1B0` 的线程 ID）
   → 崩在 `0x1B0`。**已修**（`dm_plat_set_current_thread`），等验证。

## 五、读真机崩溃报告（这次全靠它定位）

- 用户导出路径：设置 → 隐私与安全性 → 分析与改进 → 分析数据 → `DmGame-*.ips`
- 第一行是 JSON 头，其余是 JSON 体。看：`exception`（类型/故障地址）、
  `termination`、`faultingThread`、`usedImages`（确认库有没有加载）、
  `threads[].frames[]`（带 `symbol`/`imageIndex` —— 直接给出崩在哪个函数）。
- 客户的 log（`Documents/dm-log.txt`）在 App 内，**下次启动会显示在屏幕上**，
  用「第一行（带构建标记 r49/rXX）+ 上次运行最后几行」这两段来汇报最有效。
