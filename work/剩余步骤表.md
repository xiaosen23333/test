## 二、本轮改了什么

### 1. 启动序列顺序（这就是卡死的原因）

D2R 的记录（上一版代码开头就引着这句话）：

> 「`_init_libc1` 必须最先，**略过它会在 putc 嵌套加锁时自锁死**」

而上一版把 `_init`（C++ 静态构造）放在了 `_init_libc1` **前面** ——
静态构造里只要有一次输出，就会去拿**还没初始化成递归锁**的 libc 锁 → 自锁死 → 卡住。
现在：

```
_init_libc1  →  _init（C++ 静态构造）  →  nnosInitialize  →  nninitStartup  →  nnMain
```

### 2. 门调用记录（区分「客体自旋」与「死在宿主 HLE」）

客体每次经门（svc / 读计时器）进宿主，都记下**返回点**。卡死或崩溃时会打印
「最近 4 次门调用是哪几个客体站点」—— 如果卡住是因为某个宿主实现里等一个永远不来的锁，
一眼就能看出是哪个门。

### 3. 看门狗（崩溃能抓信号，**卡住没有任何信号**）

外壳另起一个线程：帧循环心跳 8 秒不动就写一行 `[看门狗]`（含当前阶段 + 最近门调用）。
因为主线程被客体占住时屏幕刷不动，这一行**只在下次启动的日志尾部里看得到**。

### 4. 检查脚本补了一类

文件作用域 `static` 变量「用在声明之前」（变量**没有**前向声明）。
本轮真踩到：`g_heartbeat` 的声明写在了 `frame_tick` 后面 —— 函数检查抓不到这一类。
