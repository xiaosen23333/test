（比 ipa 大小、整包哈希可靠得多）。

### 本轮新增的诊断通道（下个对话一定要懂它）

**背景认知（重要，别再犯）**：客体（游戏）**跑在主线程上**
（CADisplayLink → `frame_tick` → `dm_host_frame` → `dm_host_enter_guest` → `nnMain`）。
客体一旦不返回，主线程就被占住 —— **屏幕上的字再也不会更新**。
所以「只看屏幕」这条路的上限很低：它只能告诉你「进客体之前」发生了什么。

因此加了两条通道：

| 通道 | 在哪 | 谁写 |
|---|---|---|
| **日志文件** `<Documents>/dm-log.txt`，每条**立刻 fflush** | `hle_diag.c` | 宿主与客体都写 |
| **上次运行日志的尾部直接显示在屏幕上**（每次启动读一次） | `front_ios.m` 的 `log_tail()` | iOS 外壳 |

打标记的位置：

| 文件 | 标记 |
|---|---|
| `hle_nvn_boot.c` | 装载开始 / 每个模块装载成功 / 失败是第几个 / 装载摘要 / 帧循环第一次被调 / 进客体 / 没有入口点 |
| `hle_nvn_guest.c` | **启动序列五步各两条**（「调用 X」写在调用**之前**） |

所以：**卡死或崩溃在哪一步，日志最后一行就是答案。**
「五步的先后」正是上一份交接文档里唯一没验的东西 —— 现在能验了。

### 一行总览（屏幕第二行）

```
客体 3/5 调用 nninitStartup | 录 1200 放 1180 丢 0 | 本帧 pass 1 draw 0 present 0
```

- `录` 在涨 = 客体真在调 NVN；`放` 在涨 = 宿主真在翻成后端操作；`丢` >0 = 环形缓冲录不过来
- `draw 0` = 绘制命令没能进 Metal；`present 0` = 一次都没提交
- `draws_no_target`（可加进总览）= 想画但没有渲染目标，**黑屏最典型的原因**

## 五、这一路踩过的坑（**务必看，别重复**）

### ① 「先调用、后声明」在 clang 16 起是**硬错误**（本轮新踩）

```
error: call to undeclared function 'status_set';
       ISO C99 and later do not support implicit function declarations
```

front_ios.m 里两处（`status_set` 定义在使用之后、`dm_ios_start` 同理）。
**Windows 上没有 ObjC 编译器，这永远看不出来** —— 一推给朋友就是一整轮白跑。
对策：`work/porting/check_use_before_decl.py`（已接进同步脚本与 CI）。
`nn_selftest.c` 里也有 4 处同类（MSVC 只警告 C4013，所以一直没暴露）。

### ② 手写的「要同步哪些文件」清单**本身就是 bug 来源**（犯过两次）

- 第 41 轮：只更新了①②、没同步③ → 朋友白编一次，二进制逐字节相同（CRC `e81954f3`）
- 第 43 轮：`main.m` 不在同步清单里 → 又要重建仓库才发现

对策：`sync_to_build_repo.py` 改成**整目录镜像**（`work/host/**`、`work/ios/**`），
新增文件自动带上，并反向核对「仓库里有、工作区里没有」的文件。

### ③ 三份代码必须分清

| 份 | 位置 | 用途 |
|---|---|---|
| ① 工作区 | `work/host/`、`work/ios/` | 我改代码、跑 17 个自测 |
| ② 交付包 | `work/dist/dm-mac-build-kit.zip` | 发朋友（现在基本不用了，CI 更快） |
| ③ 编译仓库 | `work/d2r-mobile/` | CI 真正编译的那份 |

### ④ 验证「壳是不是真的重编了」不要看 ipa 大小

重新打包会因时间戳改变整包哈希，但里面的可执行文件可能一模一样。
**要比可执行文件本身**：`fetch_ci_shell.py` 现在会自动查几个新符号。
最可靠的判据：Mach-O 里留有编译单元名与编译器路径。

### ⑤ 签名

| 工具 | 结果 |
|---|---|
| **Sideloadly** | ✅ 可用（用户已验证装上了） |
| 爱思助手「IPA 签名」 | ❌ 不可用 —— 重打包时**弄丢所有 Unix 权限位**，iOS 报「无法验证其完整性」 |

### ⑥ 工具与转义（犯过约 10 次）

- 不要用 shell 内联脚本改源码（`\n`、引号、`!!`、`$OUT`、heredoc 全会出问题）。
  **写成 .py 文件再跑**，并核对替换是否真的生效。
- PowerShell 的 `.ps1` 含非 ASCII 必须带 UTF-8 BOM。
- Windows 命令行上限 32767 字符（批量传路径要按字符总长分批，`WinError 206`）。
- **读 git 输出的中文路径要加 `-c core.quotepath=false`**，否则被转义成 `\347\273…`（本轮踩过）。

### ⑦ 遇到「这个值从哪来 / 会不会被调用」，先查调用点或参考实现，再动手

三次大弯路：MOD0 猜入口（该查 dynsym）、glslc 当硬阻塞（该查会不会被调用）、
从一行 `str x0` 推断「回调参数」（该查**谁读那个全局**）。

### ⑧ 认证：CI 产物要登录才能下载

匿名能列出 artifact，下载会 401。而且产物会 **302 到 Azure Blob 的预签名地址**，
**不能**把 Authorization 带过去（带过去 Azure 回 401）。`fetch_ci_shell.py` 里
用自定义 redirect handler 剥掉它。凭据来源：本机 git 已存的 `gho_` 令牌。
