## 一、真因（前两轮的「卡在第 1 步」都是它）

`loader.c` 的映射只有 **可读可写**：

```c
mmap(NULL, n, PROT_READ | PROT_WRITE, MAP_PRIVATE | MAP_ANON, -1, 0);   // 没有 PROT_EXEC
```
而**内核不会执行不可执行的页** → 跳进客体、执行第一条指令 → 直接没了。

### 为什么前两轮看不出来（三个误导点，记下来）

| 现象 | 为什么有误导性 |
|---|---|
| 宿主标记全都正常（"切栈进客体"、"调用 _init_libc1…" 都打出来了） | 那些标记是**宿主代码**在执行（guest_main 在我们自己的可执行页里） |
| 之后**既没有崩溃行、也没有看门狗行** | 执行不可执行的页在 iOS 上往往被内核直接处理掉，信号处理来不及/不触发 |
| 把第一个调用从 `_init` 换成 `_init_libc1`，症状**一模一样** | 因为出事的是「第一条客体指令」本身，跟调哪个函数无关 |

> 一句话：**我们看到的最后一行日志，恰好就是"即将执行第一条客体指令"的那一刻。**

### 修法

新增 `dm_loader_finalize()`：重定位做完之后、进客体之前，按 fixups 的段边界设页保护 ——
代码段与**改写器补丁区** → `R+X`；rodata → `R`；data/bss/键页 → `RW`。
`hle_nvn_boot.c` 在重定位循环之后对 5 个模块各调一次，并把失败段数写进日志
（`页保护已设好…失败 N 段`，N>0 就说明 iOS 拒绝了某一段，日志会指出是哪段）。
