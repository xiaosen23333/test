# 给朋友的操作说明（Mac / GitHub Actions 上要做的事）

**目标**：把这个仓库编译成 iOS 安装包（叫「壳」），交回给我。

**你不需要有这台游戏的任何文件。** 壳里**不含任何游戏内容**，游戏文件全程在我这边。

**你会拿到两份东西，用其中任意一份都行**：

| 交给你的 | 怎么用 |
|---|---|
| **A. 一份源码压缩包**（`dm-mac-build-kit.zip`，0.21 MB） | 在 Mac 上本地编（第三节） |
| **B. 一个 GitHub 仓库**（你已经有 CI 工作流） | 推上去让 Actions 编（第四节） |

**两条路产出的东西一样**，选你方便的。

## 〇、先说清预期：这一版编出来的是什么

| 项 | 状态 |
|---|---|
| 能不能编过 | ✅ **应当能**（宿主 6,600 行 + iOS 外壳已在 Windows 上编过、17 个自测全过） |
| 编出来的 App 能不能**启动** | ⚠️ **可能启动，但不保证** —— 有两处必须真机调试才能定 |
| 启动后能不能**看到画面** | ❌ **不能** —— Metal 编码层还只写了骨架（3 个 TODO） |

**所以这一轮的产出意义是**：把「能编译、能签名、能安装、能启动、能看到日志」这条链路打通。
**能编过就已经很有价值了** —— 它证明 Windows 上写的代码在 clang 下也合法，
而这是我在 Windows 上无法验证的。

**如果编译报错，那是我这边的问题，不是你的** —— 把错误整段贴回来就行。

## 三、路线 A：在 Mac 上本地编译

```bash
cd dm-mac-build-kit/work/ios
xcodegen generate
```

应当看到 `Created project at .../DmGame.xcodeproj`。

### ① 先做一次「只为看能不能编过」的编译

```bash
xcodebuild -project DmGame.xcodeproj -scheme DmGame \
           -sdk iphoneos -configuration Release \
           -destination 'generic/platform=iOS' \
           CODE_SIGNING_ALLOWED=NO \
           build 2>&1 | tail -60
```

- ✅ **成功** → 走 ②
- ❌ **失败** → 跳到第六节，把错误贴回来

> `CODE_SIGNING_ALLOWED=NO` 是故意的：先确认**代码本身能编**，签名留到最后。

### ② （强烈建议）用你自己的 Apple ID 装到真机跑一次

**这一步能提前暴露「链接缺库」「Info.plist 项不对」这类问题**，比只编过更有价值。

1. `open DmGame.xcodeproj`
2. 选 target `DmGame` → Signing & Capabilities → 勾 `Automatically manage signing` → Team 选你的 Apple ID（免费的就行）
3. 插上 iPhone/iPad，顶部选它，点 **Run**

**预期结果**：App 起得来，但显示
**「还没准备好 / 请把游戏 RomFS/data 里的 .data 档案拷进本 App 的文件夹」** ——
**这是正确的**，因为壳里没有游戏内容（`main.m` 里那段就是为此写的）。

- 如果**真的弹出这个提示** → 说明宿主启动到了检查资源那一步 ✅ **这是好消息**
- 如果**直接闪退** → 把 Xcode 控制台输出贴回来

### ③ 出「壳」并交回

```bash
cd dm-mac-build-kit/work/ios

xcodebuild -project DmGame.xcodeproj -scheme DmGame \
           -sdk iphoneos -configuration Release \
           -derivedDataPath ./build \
           -destination 'generic/platform=iOS' \
           CODE_SIGNING_ALLOWED=NO \
           build

cd ./build/Build/Products/Release-iphoneos
mkdir -p Payload
cp -R DmGame.app Payload/
zip -qry DmGame-shell.ipa Payload
ls -lh DmGame-shell.ipa
```

**把 `DmGame-shell.ipa` 发回来**（大约 30 KB ~ 200 KB，很小是正常的）。

## 四、路线 B：用 GitHub Actions 编（你已经有工作流）

如果仓库已经在跑 CI，只要确保**代码是最新的**，然后 push：

```bash
cd <你的仓库>
git add -A
git commit -m "sync: 资源目录修正（iOS 用 bundle 绝对路径）"
git push
```

**push 前请确认这 5 个文件的改动进去了**（这是上一轮漏掉、导致白编一次的原因）：

```bash
git status --short
#   M work/host/hle_nvn_boot.c      改用 dm_host_res_dir()
#   M work/ios/front_ios.m          实现 dm_ios_res_dir()
#   M work/ios/project.yml          加 hle_host_dir.c
# ?? work/host/hle_host_dir.c       新增
# ?? work/host/hle_host_dir.h       新增
```

**特别注意 `??` 那两个** —— 它们是**新增文件**，`git add -A` 才会带上。
上一轮就是因为它们没进 commit，编出来的二进制与上一次**逐字节相同**。

### 建议在 workflow 里加一道「清单核对」

**编译前**打印一次源文件清单，这样缺文件会立刻看出来：

```yaml
      - name: 确认源文件齐全
        run: |
          echo "=== work/host 下的源文件 ==="
          ls -1 work/host/*.c work/host/*.h work/host/*.m work/host/*.S 2>/dev/null | wc -l
          echo "=== 关键文件点名 ==="
          for f in work/host/hle_host_dir.c work/host/hle_host_dir.h \
                   work/host/hle_nvn_guest.c work/host/entry.S \
                   work/host/dm_guest_entry.S work/host/hle_nvn_mtl_apply.m \
                   work/host/nvn_thunks.bin; do
            [ -f "$f" ] && echo "  有 $f" || echo "  **缺 $f**"
          done
          echo "=== project.yml 引用的文件是否都在 ==="
          grep -o '\.\./host/[A-Za-z0-9_.]*' work/ios/project.yml | sort -u | while read p; do
            t="work/ios/$p"
            [ -f "$t" ] && echo "  有 $p" || echo "  **缺 $p**"
          done
```

**这一段能自动抓到「文件没推上去」和「project.yml 列了不存在的文件」两类问题。**

## 六、可能遇到的问题

| 现象 | 原因与处理 |
|---|---|
| `xcodegen: command not found` | `brew install xcodegen`；或 `brew` 不在 PATH |
| `error: invalid integral value '-O2' in '-O-O2'` | 已修 —— `GCC_OPTIMIZATION_LEVEL` 只填 `-O` 后面的部分（`"1"`/`"2"`）。若还报，说明 `project.yml` 是旧版 |
| `'hle.h' file not found` | 已修 —— 靠 `HEADER_SEARCH_PATHS: $(SRCROOT)/../host`。若还报，说明 `project.yml` 是旧版 |
| `call to undeclared function 'mincore'` | 已修（加 `<sys/mman.h>`）。旧版才会报 |
| `call to undeclared function 'ftruncate'` | 已修（加 `<unistd.h>`）。旧版才会报 |
| `conflicting types for 'dm_host_current'` | 已修。旧版才会报 |
| `use of undeclared identifier 'dm_nn_InitializeSystemEvent'` | 已修（`hle_nn_more.c` 加了自己的头）。旧版才会报 |
| **`_dm_ios_res_dir` 未定义** | **上一轮的缺口**：`hle_host_dir.c` 里调它，但 `front_ios.m` 没实现。**新版已实现**；若还报，说明 `front_ios.m` 是旧版 |
| **编出来与上次逐字节相同** | 新文件没进 commit —— 见第四节 |
| 汇编报错在 `entry.S` / `dm_guest_entry.S` | 确认 `ARCHS` 是 `arm64`，且这两个文件标了 `buildPhase: sources`（新版已标） |

**报错请整段贴回来**（含上面几行上下文），不用自己琢磨。
