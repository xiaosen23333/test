# 给朋友的操作说明（Mac / GitHub Actions 上要做的事）

**目标**：把这个仓库编译成 iOS 安装包（叫「壳」），交回给我。

**你不需要有这台游戏的任何文件。** 壳里**不含任何游戏内容**，游戏文件全程在我这边。

**你会拿到两份东西，用其中任意一份都行**：

| 交给你的 | 怎么用 |
|---|---|
| **A. 一份源码压缩包**（`dm-mac-build-kit.zip`，0.22 MB） | 在 Mac 上本地编（第三节） |
| **B. 一个 GitHub 仓库**（你已经有 CI 工作流） | 推上去让 Actions 编（第四节） |

**两条路产出的东西一样**，选你方便的。

## 〇、这一次只要 3 条命令（第 3 次麻烦你，内容与上次一样）

改动只有 3 个文件（2 个新加的 + 1 个改的），**编译方式完全没变**：

```bash
brew install xcodegen                     # 已装过就跳过
cd <仓库>/work/ios && xcodegen generate
xcodebuild -project DmGame.xcodeproj -scheme DmGame \
           -sdk iphoneos -configuration Release \
           -destination 'generic/platform=iOS' \
           CODE_SIGNING_ALLOWED=NO build 2>&1 | tail -40
```

**`CODE_SIGNING_ALLOWED=NO` 保持不变** —— 签名我们这边用自签工具做（已跑通）。

### 这次改了什么（都在 `work/host/`、`work/ios/`）

| 文件 | 状态 | 做了什么 |
|---|---|---|
| `work/host/hle_host_dir.c` | **改** | 新增 `dm_host_data_dir()`：游戏数据**先在 App 包里找，找不到才去 Documents** |
| `work/host/hle_host_dir.h` | **改** | 加对应声明 |
| `work/ios/front_ios.m` | **改** | 加 `dm_ios_docs_dir()`；启动时用 `dm_host_data_dir()` |

**为什么要这样改**：原来游戏资源必须由用户手工拷进 App 的 Documents，
而这一步**在 iPad 上很容易出错**（路径错、少拷、拖错位置），
而且它的错误**很难和别的问题区分开**。
改成「包里优先」之后，只要打包时把资源放进去，用户**装上就能跑，不用碰文件**。

## 四、路线 B：用 GitHub Actions 编

```bash
cd <你的仓库>
git add -A
git commit -m "sync: 游戏数据先在包内找，找不到再退回 Documents"
git push
```

**push 前确认这 3 个文件的改动进去了**：

```bash
git status --short
#   M work/ios/front_ios.m
#   M work/host/hle_host_dir.c     ← 注意：它已是跟踪文件，改的是内容
#   M work/host/hle_host_dir.h
```

> 上一轮你漏掉了两个 **`??` 新增文件**，导致编出来的二进制与上一次逐字节相同 ——
> 所以这次**务必先 `git status` 看一眼**。

### 建议在 workflow 里加一道「清单核对」

编译**前**打印一次源文件清单，缺文件会立刻看出来：

```yaml
      - name: 确认源文件齐全
        run: |
          echo "=== 关键文件点名 ==="
          for f in work/host/hle_host_dir.c work/host/hle_host_dir.h \
                   work/host/hle_nvn_guest.c work/host/entry.S \
                   work/host/dm_guest_entry.S work/host/hle_nvn_mtl_apply.m \
                   work/host/nvn_thunks.bin; do
            [ -f "$f" ] && echo "  有 $f" || echo "  **缺 $f**"
          done
          echo "=== project.yml 引用的文件是否都在 ==="
          grep -o '\.\./host/[A-Za-z0-9_.]*' work/ios/project.yml | sort -u | while read p; do
            t="work/ios/$p"
            [ -f "$t" ] && echo "  有 $p" || echo "  **缺 $p**"
          done
```

## 六、可能遇到的问题

| 现象 | 原因与处理 |
|---|---|
| `xcodegen: command not found` | `brew install xcodegen` |
| `error: invalid integral value '-O2' in '-O-O2'` | 说明 `project.yml` 是旧版（新版写的是 `"1"`/`"2"`） |
| `'hle.h' file not found` | 旧版（新版有 `HEADER_SEARCH_PATHS`） |
| `call to undeclared function 'mincore'` | 旧版（新版加了 `<sys/mman.h>`） |
| `call to undeclared function 'ftruncate'` | 旧版（新版加了 `<unistd.h>`） |
| `conflicting types for 'dm_host_current'` | 旧版（新版删了重复声明） |
| `_dm_ios_res_dir` / `_dm_ios_docs_dir` 未定义 | `front_ios.m` 是旧版（新版两个都实现了） |
| **编出来与上次逐字节相同** | 有文件没进 commit —— 见第四节，先 `git status` |
| 汇编报错在 `entry.S` / `dm_guest_entry.S` | 确认 `ARCHS` 是 `arm64`，且这两个文件标了 `buildPhase: sources` |

**报错请整段贴回来**（含上面几行上下文）。
